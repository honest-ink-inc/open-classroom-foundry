# Data inventory and lifecycle (Gate 0 artifact)

**Date:** 29 August 2026 · **Last revised:** 1 September 2026 · Maintained with every change to where bytes can live (Gate 5 change control). One row per store; "content" means instructional or personal content, as opposed to configuration and identifiers.

| Store | Location | Holds | Lane ceiling | Lifecycle | Purge |
|---|---|---|---|---|---|
| Session byte store | Process memory only | Captured/normalized source bytes behind opaque references | Amber (Restricted is blocked upstream) | Active session only; no autosave, no recovery journal, no thumbnails | `Release`/`PurgeAll` zero managed buffers; verified after completion **and** cancellation; OS residue (pagefile, crash dumps, spooler) is the documented forensic boundary, tested not denied |
| Board-verification working set | Process memory only: Board-to-Brief intake and the local Windows OCR capability | A decoded view of the normalized image; exact platform line text aligned to OCR candidate words, source-line boundaries and separators, and recognizer-language tag; teacher resolutions or illegible marks; teacher-assigned roles and reading order | The public Board-to-Brief intake advances only teacher-confirmed Green material; its local OCR service neither lowers nor re-decides the source lane | Intake lifetime only. After successful source purge, the verified line-and-role values move into the existing module table; the intake itself creates no artifact, approval, save, print, export, log, or network request | The service zeroes its owned PNG copy after the platform call, and the owning capture session must purge its source/normalized buffers before verified lines can return. Before every terminal handoff, the decoded image is cleared/disposed and transient control/transcript references are cleared; the verified result values intentionally survive for the module-table handoff. Direct disposal cancels and settles active OCR before purge rather than releasing a still-borrowed buffer; capture-surface failure and an unexpected terminal OCR fault also converge on purge. Managed OCR/transcript strings are **not** claimed byte-zeroed; pagefile and crash-dump residue remain the documented OS boundary |
| District policy | `%ProgramData%/OpenClassroomFoundry/policy/policy.json` | IT-controlled configuration: endpoints, provider/deployment ids, lane ceiling, cloud toggle, optional safeguarding procedure text | No content | Read once per process under a 64 KiB raw-byte cap, strict UTF-8/JSON depth 8, and an exact case-sensitive root contract. Every endpoint must be an absolute HTTPS URI without user information; an empty, oversized, unreadable, unknown, missing, duplicate, case-confusable, malformed, or incomplete grant fails closed to Offline. The transient byte buffer is zeroed after parsing. | IT-managed |
| Teacher preferences | `%LocalAppData%/OpenClassroomFoundry/preferences.json` | Locale/print conveniences | No content | Teacher-managed; corrupt ⇒ harmless reset | Delete file |
| Teacher symbol shelf | Teacher-chosen directory (`LocalSymbolStore`) | Teacher-added symbol files + provenance (meaning, alt text, teacher-stated rights) | Green only — **product-owner-adopted R2-8 engineering constraint:** public callers cannot mint or rewrite the `SymbolSubmission` capability; the trusted preflight requires teacher-confirmed Green plus a fresh metadata-stripped PNG after crop/redaction, because a photograph can contain a learner. This is not council or specialist approval. | Durable, teacher-managed; local-only by default (`LicenseRef-teacher-local`, not redistributable) | Teacher deletes; integrity verified (`VerifyIntegrity`) |
| Libre symbol pack | Repository `assets/symbols/` | Original CC0 artwork + provenance manifest | Public | Versioned in git; CI-verified hashes | n/a (public commons) |
| Green project library | Teacher-selected/district-approved directory (`.ocfproj`) | Approved Green artifacts, referenced assets with provenance, learner-audience snapshot | **Green only** — the store refuses Amber and Restricted structurally | Durable, teacher-managed ("teacher-managed" retention in manifest); reopenable forever without the application | Teacher deletes; **no approval/egress receipts inside** (R2-9) — teacher identity does not travel with a shared project |
| Approved print-view handoff | One unique `%TEMP%/OpenClassroomFoundry-print-view-{GUID}/` job, then a copy-owning same-executable child and one tokenized `127.0.0.1` HTTP response | Exact rendered bytes of an `ApprovedArtifact`; a display-derived name becomes only a bounded leaf stem, and no approval receipt is embedded | Bound to the exact approved artifact; the current three authoring surfaces enter through Green sessions, and the handoff adds no lane authority | The leased file is exclusively created, flushed, reopened read-only, and revalidated; separate fail-closed caps admit at most eight file leases and eight helpers. The child generates a random 32-hex UUID path token, copies and hash-verifies at most 32 MiB, tolerates nuisance connections, and serves one exact `GET` under a 10-second absolute deadline; the parent accepts only exit 0 within its 12-second observation | Parent `finally` closes the lease and attempts deletion or quarantine after success or failure; startup/shutdown sweeps retry residue. The parent zeros its handoff byte array and the child zeros its owned byte array. Browser cache, pagefile, crash dumps, filesystem remanence, and print spool remain OS residue and are not claimed purged |
| Diagnostics | In-memory sink (production sink not yet built) | Identifiers, states, durations, counts — content-free by policy, enforced loudly | No content, ever | Session; future remote telemetry off by default, allowlisted by district policy | n/a |
| Inference egress | District-allowlisted endpoint only, after Gate A confirmation and the policy gate (R2-1) | The exact previewed payload, nothing else | ≤ district `MaximumLane` | Stateless request through a provider-owned transport with automatic redirects disabled. The target is rebuilt from the normalized approved origin plus one bounded deployment segment and an escaped API-version query value. One 100-second deadline spans token acquisition, headers, and response body; success/error bodies that require inspection are bounded to 1 MiB, strict UTF-8, JSON media type, and depth 16, while body-independent status classes are mapped without opening the body. Every 3xx fails closed, and no thread/history or tool-call feature is accepted. | Provider retention is a Gate 3 attestation matter, never an application claim |

**What does not exist anywhere:** student profiles, rosters, longitudinal records, recipient lists, credentials in files, content in logs, or any Restricted-lane material — excluded structurally through 1.x (plan §2 non-goals).
