# Release requirement → implementation → test traceability

**Opened:** 30 August 2026

**Authority:** [Implementation plan §11, Universal Definition of Done](../implementation-plan.md#11-universal-definition-of-done) and [§19, Stop-ship conditions](../implementation-plan.md#19-stop-ship-conditions)

**Scope:** the current source tree and its evidence, not a signed release

This matrix makes every release requirement point to an implementation or evidence artifact and, where the requirement is mechanically testable, to regression evidence that can disprove it. Otherwise it names the required human, district, protected-seat, or exact-release evidence and records its absence. It is not a release certificate. A passing test does not manufacture an expert judgment, a pilot result, a district decision, a signature, or a typist's outward-facing act.

## Status vocabulary

| Status | Meaning |
|---|---|
| **Machine-proven** | A deterministic test or CI gate directly exercises the current implementation. It must run again against the exact release commit and artifact. |
| **Partial** | Useful implementation and test evidence exists, but the whole requirement is not closed. The named remainder stays open. |
| **Human/protected open** | Evidence belongs to a named human or protected seat. Code and elapsed time cannot substitute for it. |
| **Typist/district open** | Completion changes external state or depends on district-controlled devices, policy, identity, or signing material. |

Paths in the test column name the durable regression evidence; release evidence must also retain the exact command, result, commit, artifact digest, the conclusions of both CI and CodeQL, and the CodeQL SARIF artifact. CI and CodeQL provide post-push evidence and encode release policy; workflow text neither configures nor proves branch-protection enforcement.
