## Pre-publication check (run before anything becomes newly visible)

**Added 30 Aug 2026, because its absence cost something.** The repository was made public on 29 August with the seeded-error study’s answer key inside it. No forks, stars, or watchers were observed, and no participant was known to have the URL; the unavailable traffic interval cannot be reconstructed, so “nothing was lost” is not claimed. Nothing had *prevented* the exposure either. Every other rule in this project governs what **enters** the repository; that failure was a **visibility change**, and content that is harmless while private can be harmful the instant it is public.

Run this before a visibility change, a release, a site publish, or a public filing. It is short on purpose.

| # | Check | Why |
|---|---|---|
| 1 | **Scan the whole history, not the working tree.** `gitleaks git .` over full history, using the repository-pinned archive SHA-256 rather than a checksum downloaded beside the payload, plus a manual pass for emails and deleted files (`git log --all --diff-filter=D --name-only`). | Publishing publishes every commit ever made. Removing a file today does not unpublish it tomorrow. The pinned gitleaks digest was copied from the official `8.30.1` release checksum and independently matched before extraction or execution. |
| 2 | **List what becomes readable that was not.** Ask of each: would this harm anyone, or invalidate anything, if a participant, a district, or a stranger read it? | The key was not a credential and no scanner would ever have flagged it. Only a person asking this question finds that class of thing. |
| 3 | **Check the claims, not just the contents.** Does the README, the site index, and every status line say something true *today*? | The front page said "No application code exists yet" while 665 tests were passing. A false claim published is worse than an unpublished truth. |
| 4 | **Name what the act cannot be undone.** Write down what becomes permanent — an indexed page, a public filing, an archived clone. | ADR-006 holds a counsel checkpoint in front of public use of the name; a USPTO filing is public and permanent in a way a website is not. |
| 5 | **Confirm every gate by reading its conclusion**, not a wrapper’s exit code. Read both CI and CodeQL for the exact commit, and retain CodeQL's SARIF artifact with the release evidence. | CI was twice reported green while red, because `gh run watch --exit-status` was trusted instead of the run’s own `conclusion`; a missing SARIF file is missing security evidence. |

A finding at step 2 is not automatically a stop. Historically, the typist chose to publish after the facilitator replaced the external study instrument and regenerated the packets. Rendering is one command, but designing and reviewing a new instrument and key is protected human work. That historical choice is not standing authority for any future publication. The point of the check is that an authorized decision is *made*, not stumbled into.
## Rollback drill (documented procedure)

1. Every release is a signed tag; `git checkout <previous-tag>` + `tools/publish.ps1` rebuilds that pinned source for the explicit `win-x64` runtime. The SDK, repository source map, portable project locks, and separate application RID locks are pinned, but byte-identical packaging has not been measured and is not claimed.
2. The kill switch is policy, not code: IT sets `CloudInferenceEnabled=false` (or deletes `policy.json` — absence fails closed) and every device refuses egress at the provider boundary on next launch, no redeploy needed.
3. Retain the prior application and source library unchanged. The current engine reads and verifies the recorded frozen schema-1 packages and can prepare a separately validated candidate copy under proposed ADR-007. Reverse-opening a context-enriched current package in an older binary is **not** claimed; rollback returns to the retained prior library until a real managed-device drill proves more.
