# Sightings register

**Opened:** 1 September 2026 (fifth forge menu, item 1)

**Authority:** the current handover's standing instruction to keep every recorded sighting and its distinct signature open until measurement earns a diagnosis; [P-07, documented known failure modes](../release/release-requirement-test-traceability.md); the [forge closeout's recorded debts and sightings](../handover/2026-08-30-forge-closeout.md).

**Scope:** every test failure this repository has recorded as a sighting: a failure observed under load or in a hosted run that passed alone afterwards, whose cause is not established. Before this register opened, those rows lived across four handovers and the traceability matrix. This is now the one place a sighting is named, dated, and kept open. The handovers keep their narrative; this file keeps the inventory.

## The rules of the register

- These are **sightings, not diagnoses**. A row records what was measured, never a cause.
- **A passing rerun is a non-reproduction.** It is recorded, and it never closes a row. Only a measured diagnosis, recorded in a dated note that names its evidence, changes a status.
- **Rows are never deleted.** A row that earns a diagnosis is struck in place with a dated note and keeps its number.
- **Raising a timeout is not a fix.** The last flake that was chased with a longer wait turned out to be a real seam. Instruments reproduce load; they do not extend deadlines.
- **The guard:** [SightingsRegisterTests](../../tests/Unit/SightingsRegisterTests.cs) fails whenever any governing record under `docs/` names a test identifier on the same line as the word *sighting* and this register does not carry that identifier, whenever a register identifier names no real test, and whenever the row tables lose their order or vocabulary.

## Status vocabulary

| Status | Meaning |
|---|---|
| Open sighting | Observed, retained, not diagnosed. Every rerun since is a non-reproduction. |
| Deterministic, repaired | Named on a sighting line in a record, but measured as a deterministic contract failure and repaired. Listed only so the guard stays exhaustive and a reader does not mistake it for a sighting. |
| Deterministic, context-bound, undiagnosed | Fails every time in one named process context and passes in another on the same machine and tree. Not a load sighting, because it does not pass alone in the context that fails; not repaired. Listed so the next hand starts from the measurement rather than from a hunch. |

## The guard

[SightingsRegisterTests](../../tests/Unit/SightingsRegisterTests.cs) reads every Markdown file under `docs/` except this one. On every line that contains the word *sighting*, it extracts each test identifier written as a class name ending in *Tests*, a dot, and a method name containing an underscore, and each `console-signal.` token, and fails if this register does not carry it. It also fails if a register identifier names no method in a matching test source file, if a token is absent from the console-control sender, if the S and N rows are not sequential, complete, and in their closed vocabulary, or if a relative link here does not resolve. The guard cannot judge whether a row is honest; a hand still reads the record it cites.

## Adding a row

1. Retain the evidence first: run identifier, receipt identifier, TRX hash, duration, and the exact failure name and message.
2. Add the next S row with the signature, class, first observation, retained observations, and the instrument that can seek an equivalent-load reproduction. If none exists, say so.
3. Cite the run in the [evidence ledger](evidence-ledger.json) rather than restating it in a handover.
4. Never raise a deadline as part of the same change. If a later measurement earns a diagnosis, strike the row in place with a dated note and its evidence.
